## 要解决的问题

统一单位的 token 单价可以直接比较，但不足以说明实际工作量的月费。这个产品把不同模型放在相同请求数和输入、输出 token 量下计算预计费用，帮助开发者选择候选模型做实际任务测试。

## 我做了什么

- 用 Python 从 OpenRouter 公开目录导入一个带日期的 80 个文本模型快照，整理统一价格单位与可用评测字段。
- 用 JavaScript 实现响应式页面、模型搜索、价格表、工作量输入和模型详情链接。
- 实现按公开的提示词长度价格档位计算的费用估算器，以及随工作量变化的实验性“评测分数/费用”候选榜单。
- 通过 Cloudflare 发布可直接访问的产品，访客无需提供模型 API Key。

## 可以体验的功能

1. 打开产品，切换模型，修改每月请求数和每次请求的输入、输出 token 数。
2. 在模型表格中比较重新计算的费用，通过搜索和筛选缩小范围。
3. 查看性价比候选榜单及数据说明。“美国开发公司”筛选指模型开发者，不代表运行或托管地点。

## 结果与适用范围

已交付一个公开可访问的交互产品，同一组工作量同时驱动价格比较与候选榜单。公开目录包含 80 个模型；此前已在 320 px、390 px 宽度检查响应式布局，小屏幕下表格在自身容器内横向滚动。

价格为带日期的目录快照，不是实时结算报价。估算仅覆盖文本输入与输出，不包含缓存、工具、多模态、税费和路由实际计费差异。评测分数与费用的比值用于筛选待测试候选，不能代表客户具体任务的效果；模型是否可用还取决于提供方的账号与地域规则。这是本人自有产品，没有声称客户成果或节省金额。
